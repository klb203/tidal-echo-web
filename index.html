上下文迟早要清，但不该由你操心。开启后这套东西在后台自动跑：
            ① 推送——老内容先摘要落进记忆（游标落后够条数才动手，不是定时器）；
            ② 重铸——摘要安全落库之后，才把老消息从活上下文里剪掉，并在聊天里留一张可折叠的总结卡；
            ③ 线头——顺手记下「还差一句话没说完」，下次接得上；
            ④ 空闲检查点——以上都在你停止打字之后才做，绝不在你等回复时动手。
            
会话本身不动：不用开新会话，也不用你手动清理。

不再由你先开口。
            做法不是「单独让 AI 写一条问候」（那样出来的一定是万金油，客服味的来源），
            而是影子路由：取真实会话最近几条 → 末尾临时塞进一条永不落库的
            <system_trigger>（状态 + 素材 + 指令）→ 用和聊天完全一样的 system prompt
            调用 → 回复按普通消息存进会话。
            
所以在模型眼里这次调用和正常聊天没区别：它有你们的关系、有昨晚聊到哪儿、有自己的语气。
            也正因为复用同一份 system prompt，它还会命中正式聊天建好的那段前缀缓存——
            按教程的建议，影子调用不标新缓存（每次消息排布不同，标了只会白花钱建命中不了的缓存）。
            
先决定该不该说，再决定说什么：过不了决策层（深夜保护 / 随机冷静期 / 每日上限 / 互斥锁），
            连一个 token 都不花。

        那一桶语义原话，世界书是它自己长出来的叙事，档案馆把上面这些按年月归到一处。

        宫殿是长期那一半 —— 它把聊天里值得留下的提纯成情景节点，按房间归位
        （客厅 / 卧室 / 书房 / 用户房 / 自我房…），重要的进门牌：每轮注入、不衰减。
        召回靠质量不靠数量（三路融合后按稀有度与可靠度重排）。

参考项目 · 向量检索

            
同一件事（把记忆找回来）的三种做法 —— 地址可复制给 AI

          

        


        
kiwi-mem · 记忆热度 / Dream 整合 / 日历摘要

        

          
          
        

        

          kiwi-mem（Python + pgvector 自托管记忆网关）—— 三样值得抄：
          热度（时间半衰期 + 召回升温 + 情绪权重；高热度全文注入、中热度只给摘要、冷记忆不打扰）、
          Dream（夜里把碎片融成「记忆场景」，并给场景建向量索引，白天还能被搜到 ——
          睡觉的产出回流到清醒的日子）、日历层级摘要（近的详细、远的压缩）。
        


        
paramecium · 原文 + 检索

        

          
          
        

        

          paramecium（草履虫：一个不打算成为大脑的记忆网关）—— 立场最清楚的一条：
          向量是原文的投影，不是替代品。embedding 只负责指路（attention 里的 K），
          命中后取回的是一字不差的原文（V）；token 只为命中付费。
          另外两个具体做法：回复的余味（它刚说出口的那句话，单独作查询的第二路）、
          「菜单递过去就行、夹不夹菜是人格的事」（目录只给标题，翻不翻由模型自己定）。
        


        
imprint-memory · 混合检索 + MCP

        

          
          
        

        

          imprint-memory（Claude Code 的持久记忆 · MCP server）—— 混合检索那条链写得最直白：
          FTS5 + 中文分词 与 向量 cosine 并行召回，再用 RRF 按排名融合
          （分数尺度对不齐，排名对得齐）；外加 pin（永不衰减）、标签、图谱边给排名加成。
          它那节「嵌入模型不许混用 ⚠️」也是踩过坑才写的 —— 换模型就等于全库向量作废。
        


        

          这本仓库已经吸收了这几条（都能在下面「召回」那张卡的返回里看到）：
          RRF 按排名融合（关键词 / 语义 / 关联 / 它的余味，最多四路）·
          相关性地板（三路都没够格就说「没找到」，不拿沾边的去圆）·
          回复的余味（用它上一轮自己的话单独查一路，而不是拼进查询被稀释）·
          注入预算分层（按分数填字符预算，超出退成简报）·
          结果去重（太像的只留一条，名次让给真正不同的）·
          BM25 索引缓存（不再每轮全库重新分词）。

          还没做的：Dream 式夜间整合、日历层级摘要 —— 那是另一条链（近景正在做按天的那一半）。
